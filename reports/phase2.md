# 第二阶段浏览器实测记录

测量时间：2026-11-20 08:51 UTC。环境：Windows 本机无头 Chrome 157.0.8103.79、localhost 的 `/SaintScope/` 子路径、WASM 单线程、Transformers.js 4.3.2、`Xenova/clip-vit-base-patch32` 固定修订版、q8。原始逐图记录见 `phase2-browser.json`；可运行 `npm run benchmark` 复测。

## 性能

| 指标 | 实测值 | 口径 |
|---|---:|---|
| 首次模型资源网络读取 | 162.3 MiB | Worker 对 Transformers.js `fetch` 响应流逐块计数；不含同源 WASM、浏览器缓存协议开销 |
| 本地 WASM 文件传输 | 14,264,838 字节 | 测试 HTTP 服务器发送的 `ort-wasm-simd-threaded.wasm` 文件 |
| 首次模型初始化 | 5,829 毫秒 | Worker 内从开始加载到模型、分词器、图像处理器就绪 |
| 单张推理 | 1,263–1,615 毫秒 | 七张缩略图，含解码、文本编码与 CLIP 前向计算；另一轮实测上限为 3,483 毫秒 |
| 取消后重新初始化 | 919 毫秒 | 相同浏览器会话缓存命中，模型资源网络读取 0.0 MiB |
| 主页面 JS 堆 | 4,797,076–11,483,143 字节 | Chrome `performance.memory`，仅主页面抽样，不含 Worker/WASM，也不是峰值内存 |

浏览器未提供可信的进程峰值内存读数；**峰值内存未知**。`navigator.storage.estimate()` 返回缓存占用，但那是磁盘存储，不可当作内存。数据来自桌面 Chrome，不可推断手机性能。

## 异常与取消

- 在真实 Chrome 中，点击取消后状态显示“识别已取消”，迟到的结果没有显示；重新识别成功，网络读取 0.0 MiB。
- 阻断 Hugging Face 下载时，页面显示 `Failed to fetch` 并保留 24 条手动检索结果。
- 本次七图运行没有页面脚本异常。
- 本次浏览器页面没有非 GET 请求；这与代码中的本地图片处理方式一致，但不等于对所有网络环境的审计。

本地 `/SaintScope/` 子路径运行成功；尚未执行 iPhone Safari、Android Chrome、真实 GitHub Pages、离线重启或 PWA 安装测试。
